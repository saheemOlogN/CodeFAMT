CODEFAMT - FILE AND FUNCTION GUIDE
Based on the working source on 31 October 2026.

HOW TO USE THIS GUIDE
Search for a file path or function name. Paths are relative to the repository.
The README covers setup/deployment; this guide explains the code.
A component renders UI. A hook shares state/data behavior. A controller handles
an API request. Middleware checks that request. A model defines stored data.
A worker processes queued jobs outside the HTTP request.

Coverage: every project-owned tracked file, including tests, styles and config.
Named functions and local event helpers are described under their source file.
Repeated inline map/filter callbacks, React effects, schema validators and mock
callbacks are explained with their owner instead of given invented names.
node_modules, generated dist files, Git internals, private environment values and
local backups are not source files and are not enumerated. Embedded example
solution functions are learning fixtures, not application functions.

MAIN FLOWS
1. Startup: server/dev.js starts server/index.js and server/worker.js.
   Browser: client/src/main.jsx -> App.jsx -> Layout and the selected page.
2. Login: AuthPage -> AuthProvider/api -> auth routes/controller -> User.
   The browser receives an HttpOnly cookie; protected requests check it again.
3. Run: ProblemWorkspace -> runCode -> CodeRun -> queue -> processExecution.
   Public examples are checked; a Run does not award a solved problem.
4. Submit: submitCode -> saved Submission -> queue -> worker -> gradeSubmission
   -> executeCode + judgeResults -> saved verdict and unique solved record.
   Socket events/polling bring the result back to the browser.
5. Contest: AdminPage -> contest controller -> transactional publication.
   The server enforces registration, access and submission deadlines.
6. Roadmap: RoadmapPage -> roadmap controller -> shared content and personal
   completed topic IDs. Student progress is stored per account.

IMPORTANT BOUNDARIES
Run/Submit need MongoDB, Redis, the worker and compiler credentials.
Public problem responses strip hidden drivers; hidden tests require admin access.
The reset-test-content utility is destructive: use disposable development data.
Old CP fields remain for stored-record compatibility; the student flow uses DSA.
This guide describes the source; it does not guarantee production readiness.


========================================================================
BACKEND ENTRY AND CONFIG
========================================================================

server/config/compileCache.js
Enables the Node compile cache to speed up repeated dependency loading.
  No named application functions; this file defines data or configuration.

server/config/db.js
Prepares the database before requests or jobs are accepted.
  connectDB(): Connects with bounded retries, checks transaction support in production, creates model indexes and initializes required session/queue versions and the admin lock.

server/config/environment.js
Checks production settings.
  validateEnvironment(): Requires service credentials, sufficiently long signing secrets, an exact HTTPS origin, valid ports and an explicit proxy-hop count.

server/config/redis.js
Owns Redis connection creation and the shared client.
  createRedisConnection(): Creates a lazy Redis connection with retry and timeout settings.
  getRedis(): Returns the shared client, creating it on first use.
  closeRedis(): Disconnects and clears the shared client.

server/config/socket.js
Sets up authenticated realtime connections and contest rooms.
  checkLogin(): Validates a cookie/bearer token, origin, verified account, session version and expiry.
  initializeSocket(): Attaches Socket.IO, configures Redis broadcasting and registers room/authentication handlers.
  scheduleExpiry(): Schedules disconnection when the login expires.
  Socket callbacks: Recheck access for contest rooms, handle room joins/leaves, acknowledgements, disconnects and cleanup.

server/dev.js
Runs the API and worker together during development.
  startDevelopment(): Launches both Node watch processes and installs signal/error handlers.
  stop(): Stops both children; uses process-tree termination on Windows.

server/index.js
Creates the Express API, security headers, API routes, health endpoints and production frontend serving. Starts services only when executed directly.
  stop(): Gracefully closes sockets, queues, Redis and MongoDB on shutdown.
  Inline handlers: Answer liveness/readiness, reject unknown API routes, and serve the SPA. The startup callback starts HTTP only after required services initialize.

server/worker.js
Entry point for the background judge process.
  start(): Validates settings, connects services, recovers jobs, starts the worker, heartbeat, health server and recovery timer.
  stop(): Stops the health server, heartbeat, timers, worker and service connections.
  Timer/HTTP callbacks: Recover missing jobs every 15 seconds and report worker readiness.

ROUTES, MIDDLEWARE AND CONTROLLERS
========================================================================

server/controllers/activity.controller.js
Submission activity for the profile heatmap.
  getActivity(): Validate the requested year and aggregate the user’s submissions by day in India time.

server/controllers/auth.controller.js
Registration, verification and login.
  register(): Validate college registration and initiate email verification.
  verifyOtp(): Validate the OTP and create/verify the account using the submitted registration details.
  resendOtp(): Send another verification code subject to cooldown rules.
  login(): Check credentials and issue the persistent session cookie.
  logout(): Revoke sessions, clear the cookie and disconnect the user.

server/controllers/contest.controller.js
Contest schedules, participation, access and standings.
  createContest(): Validate and create a draft contest.
  getContests(): List contests with pagination and role-appropriate fields.
  getContest(): Return schedule and accessible contest information.
  updateContest(): Validate draft edits and publication; check attached problems/tests and immutable state.
  deleteContest(): Delete a permitted draft.
  joinContest(): Register the current student if contest rules allow it.
  getContestProblem(): Check contest access and return the student-safe problem.
  getLeaderboard(): Aggregate contest scores and ranks without counting repeat solves twice.

server/controllers/leaderboard.controller.js
College-wide rankings, separate from contest standings.
  getLeaderboard(): Validate department/year/problem filters and return ranked paginated results.
  The local leaderboard variable holds formatted result rows; it is data, not a function.

server/controllers/passwordReset.controller.js
Email-based account recovery.
  forgotPassword(): Create and email a reset OTP without revealing account existence.
  resetPassword(): Validate the reset code, replace the password hash and revoke old sessions.

server/controllers/problem.controller.js
Problem creation, publication and student access.
  createProblem(): Validate and create a problem draft.
  getProblems(): Return a paginated list appropriate to user access and filters.
  getProblem(): Return one accessible problem with hidden driver details removed for students.
  updateProblem(): Validate edits and publication, enforce locks and handle legacy function-template configuration.
  deleteProblem(): Delete an eligible unused draft while protecting published/referenced content.

server/controllers/profileStats.controller.js
Profile statistics.
  getProfileStats(): Aggregate practice/contest statistics and recent activity for the authenticated profile.

server/controllers/roadmap.controller.js
Shared roadmap content and personal progress.
  safeUrl(): Accept empty links or valid HTTPS URLs without embedded credentials.
  validRoadmap(): Check fields, lengths, topic limits and unique step IDs.
  text(): Local helper checking text type, length and required content.
  identifiedSteps(): Supply deterministic IDs to older steps lacking an ID.
  getRoadmap(): Return roadmap content and the current user’s valid completed steps.
  saveProgress(): Add/remove one valid topic ID on the current account.
  saveRoadmap(): Validate and save admin-authored content, assigning IDs to new topics.

server/controllers/submission.controller.js
Run, Submit, result retrieval and retry endpoints.
  submissionResponse(): Choose safe fields for submission responses.
  runCode(): Validate code/access and queue execution; example mode snapshots public examples and limits on the server.
  getRun(): Return an unexpired run result to its owner or an admin.
  submitCode(): Validate language, access, contest receipt time and tests; save executable source and enqueue judging.
  getSubmissions(): List permitted submissions with pagination.
  getSubmission(): Return an authorized submission detail.
  retrySubmission(): Requeue an eligible internal error using the original source and contest receipt.

server/controllers/testCase.controller.js
Admin-only hidden testcase management.
  importTestCases(): Validate and import JSON tests for an editable problem.
  createTestCase(): Add a hidden input/expected-output pair.
  getTestCases(): List hidden tests for authorized administration.
  updateTestCase(): Validate and change a test while its problem is editable.
  deleteTestCase(): Remove a test only while mutations are allowed.

server/controllers/user.controller.js
The signed-in user’s account and solved history.
  getProfile(): Return safe profile details and solved count.
  getSolvedProblems(): Return paginated solved records owned by the user.
  updateProfile(): Validate and save allowed profile fields.
  changePassword(): Verify the current password, save the new hash and revoke sessions.

server/middleware/admin.middleware.js
Protects administrative mutations.
  requireAdmin(): Rejects users without the admin role.
  adminWrite(controller): Wraps an admin operation in a MongoDB transaction and shared lock, buffers its response and publishes contest changes after success.
  Buffered status()/json(): Capture the controller response until the transaction commits.

server/middleware/auth.middleware.js
Protects authenticated API requests.
  requireAuth(): Reads cookie/bearer credentials, checks write origins, verifies the JWT and loads a verified user with a matching session version.

server/middleware/error.middleware.js
Shared API error handling.
  handleError(): Converts errors into suitable HTTP responses without leaking internal details.

server/middleware/rateLimit.middleware.js
Shared throttling for login, accounts, password changes and execution.
  sharedStore(name): Creates a namespaced Redis rate-limit store when Redis is configured.
  authLimiter: Limits requests by IP. accountLimiter: Limits attempts for a normalized email.
  executionLimiter/passwordLimiter: Limit requests by authenticated user ID.
  Inline keyGenerator callbacks choose the email or account ID used for counting.

server/routes/auth.routes.js
Connects URLs to middleware/controllers. Base paths are mounted in server/index.js.
  POST "/register", accountLimiter, register)

  POST "/reset-password", accountLimiter, resetPassword)
  POST "/logout", requireAuth, logout)
  These registrations are not separate business-logic functions; the controllers above implement them.

========================================================================
JUDGING AND BACKEND HELPERS
========================================================================

server/scripts/reset-test-content.js
Destructive development-only content replacement utility.
  main(): Backs up existing problem-related data, replaces test content with demo drafts/tests and the C++ roadmap, then reports the backup. Never run on real student data.

server/utils/executeCode.js
Shared backend helper for executeCode.
  executeCode(): Validate execution inputs, call the external compiler with bounded timeouts, and normalize outputs, errors and metrics.

server/utils/executionQueue.js
Shared backend helper for executionQueue.
  getQueue(): Create/reuse the BullMQ queue with retry/retention settings.
  initializeQueue(): Validate capacity, wait for Redis, enforce noeviction in production and set shared concurrency.
  enqueueSubmission(): Add a versioned submission job.
  enqueueRun(): Add a versioned run job.
  closeQueue(): Close the queue and its Redis connection.

server/utils/gradeSubmission.js
Shared backend helper for gradeSubmission.
  gradeSubmission(): Run hidden tests with saved progress, stop on failure, and persist acceptance plus the unique solve together in a transaction.

server/utils/health.js
Shared backend helper for health.
  key(): Build the namespaced heartbeat Redis key.
  readiness(): Check MongoDB, Redis and optionally a recent worker heartbeat within a timeout.
  startHeartbeat(): Register a unique worker and start heartbeat updates; return an async cleanup callback.
  beat(): Update/prune worker heartbeat records while the worker is running.

server/utils/judgeResults.js
Shared backend helper for judgeResults.
  judgeResults(): Validate compiler results, compare normalized output, enforce time/memory limits and produce verdict/counts.

server/utils/practiceAccess.js
Shared backend helper for practiceAccess.
  practiceFilter(): Build a database filter for public or released contest problems.
  canPractice(): Check whether a particular problem is available for normal practice.

server/utils/providerLimit.js
Shared backend helper for providerLimit.
  reserveProviderRun(): Use Redis to reserve a compiler request or signal that the job must wait for shared quota.

server/utils/realtime.js
Shared backend helper for realtime.
  setRealtimeServer(): Store the current Socket.IO server.
  sendRealtime(): Send through the local server or Redis emitter and handle transport failures.
  publishSubmission(): Send safe submission updates and notify contest standings after acceptance.
  publishContest(): Notify a contest room that its data changed.
  publishRun(): Send safe run status updates to the owner.
  disconnectUser(): Disconnect the account’s socket sessions.
  closeRealtime(): Close the emitter’s Redis connection.

server/utils/sendOtp.js
Shared backend helper for sendOtp.
  sendOtp(): Generate/store a hashed verification OTP, enforce resend timing and send it through SMTP.

server/utils/sessionCookie.js
Shared backend helper for sessionCookie.
  options(): Build HttpOnly, SameSite and production Secure cookie options.
  readCookie(): Extract and decode the session cookie safely.
  allowedOrigin(): Compare the request origin with CLIENT_ORIGIN.

server/utils/solutionMode.js
Shared backend helper for solutionMode.
  validDsa(): Validate per-language function templates and hidden drivers.
  publicProblem(): Strip hidden driver prefixes/suffixes from student-facing data.
  buildExecutionCode(): Combine the allowed language’s driver and submitted function code.

server/utils/startup.js
Shared backend helper for startup.
  initializeServices(): Initialize services in parallel with per-service deadlines and readable startup logs.

server/utils/testImport.js
Shared backend helper for testImport.
  validateTestImport(): Check JSON shape, testcase count, input/output types, NUL characters and byte limits before import.

server/workers/execution.worker.js
Processes queued code safely and recovers unfinished work.
  processExecution(): Claims the correct job version, grades submissions or example/custom runs, saves progress, publishes status, and handles retry/quota/permanent failures.
  recoverPendingJobs(): Finds unfinished MongoDB records and restores missing BullMQ jobs.
  createWorker(): Constructs the BullMQ worker with processing, retry/backoff and event handlers.

  Setup/cleanup hooks and anonymous mock callbacks prepare, simulate and restore the scenarios above.
